### Mac app

- One field the CLI leaves out no longer fails a whole list: a bench needs only its path, an app, a lab or a profile only its name, and one entry that does not read is skipped (and logged) while the others show. The hint for a newer CLI now says "Update BenchBar, or choose a different benchbar in Settings".
- Notifications: macOS asks about them once, with the first alert (a crash), not when BenchBar starts. A notification macOS refuses, or one that fails to send, is logged and shown in Settings, Notifications. Room notices follow the same switch.
- Small fixes: the app says plainly that it is for Apple silicon, the terminal scripts of "Run in Terminal" are per run and owner only and old ones are removed, one shared browser router and one app activation observer, the editor lookup runs only when an editor starts or quits, the `benchbar` the app starts no longer inherits stray `BENCHBAR_*` or `FL_*` variables (the ones the docs tell you to set, such as `BENCHBAR_PROFILE_PATH`, `BENCHBAR_OFFLINE`, `BENCHBAR_LABS` and `BENCHBAR_REPORT_DIR`, stay), and a leftover Caskroom folder no longer shows a wrong "Copy Command". An entry the CLI prints that the app cannot read is logged, and a list the CLI leaves out entirely is an error, not an empty list.
