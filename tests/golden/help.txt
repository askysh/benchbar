=== benchbar --help [labs: none] (exit 0)
benchbar @VERSION@: local Frappe/ERPNext bench on macOS and Linux, in the background.

Usage: benchbar <command> [options]

Setup
  install             Run phase 00 (system deps), 01 (bench and site) and the
                      background service. Safe to re-run: only changes what changed.
                      --json (with --yes or --dry-run): JSON lines for the BenchBar app.
                      --frappe-commit SHA, --erpnext-commit SHA: pin the clones (or frappe_commit
                      and erpnext_commit in a team profile); a commit the clone does not reach
                      stops the install before anything is built.
  adopt PATH         Register an existing bench: Procfile.lean, runner, agent, helpers.
                      Shows the plan and asks; never runs migrate, build or update.
                      --json (with --yes or --dry-run): JSON lines, as install.
  service             Install or refresh only the background service (phase 02).
  doctor              Read-only health report. Exit 1 when something FAILs.
                      --fix-hints: only the fix commands of FAIL and WARN checks, one per line.
                      --prerequisites: what this Mac needs before an install, no bench needed
                      (--json; --bench-dir names the folder a new bench would go to).
                      --fetch: git fetch the branches of the apps your focus apps need first
                      (without it doctor never touches the network).
                      --ack CHECK / --unack CHECK: silence one warning until its message
                      changes, or undo that. --quick: skip the slow checks and say which.
  ports setup -- PATH ...
                      Preview management/port changes, confirm once, then apply (--dry-run: preview only)
  ports plan -- PATH ...
                      Show the same read-only preview (--json: machine-readable plan and token)
  ports check         Check conflicts for --bench-dir PATH (--json)
  ports mode automatic|fixed
                      Keep automatic or fixed ports for --bench-dir PATH
  ports apply TOKEN --yes -- PATH ...
                      Apply a previously reviewed JSON plan; refuse stale approvals
  report              Redacted diagnostics zip on the Desktop for bug reports (--print: to the terminal,
                      --json: {"zip": path, "redactions": n} for the app and scripts).
  repair              Apply only the fixes doctor flagged, in dependency order.
  uninstall-service   Remove the agent, runner, Procfile.lean and shell helpers.
                      --all: every bench with a benchbar agent, after one question (before
                      brew uninstall benchbar: brew cannot stop the agents itself).
  self-update         Update the benchbar CLI and the BenchBar app with the one line installer,
                      after asking (--check: this version against the latest, --json, --dry-run).
                      A Homebrew install runs brew upgrade askysh/tap/benchbar instead.
                      Never touches a bench; never runs bench update.
  where               How this CLI was installed (homebrew, managed, checkout, other), the path
                      it records for itself, its state folder and the BenchBar app (--json).

Daily
  up                  Start the bench in the background (benchup).
                      --services-only: only its Redis, for a restore or a migrate (down stops it).
  down                Stop it and keep it stopped across reboots (benchdown).
  restart             Restart it, for example after changing Python code.
  status              State, pid, stop reason, site ping, Redis (benchstatus). --json adds
                      redis and sites[].served (does the running bench serve the site).
  stats               CPU and memory of the running bench's own processes, and the figure the
                      app's runner speed comes from (--json; resources is null when stopped).
  wait                Block until the bench is ready (site answers, socketio, Redis, a worker, code
                      not changed since the start); --for PART for one part, --timeout SECS, --json.
  list                Every bench benchbar knows about.
  scan PATH           Find benches recursively in a folder (read only; --json).
  register PATH ...   Remember selected benches without changing their services.
  logs                Tail logs/bench.log. Flags: --worker, --worker-error, --previous, -n50, --no-follow,
                      --process web|socketio|schedule|worker (worker reads logs/worker.log; with --json:
                      the lines as JSON, --since TIME or --since-restart for the newer ones only)
  fg                  Stop the service and run honcho in the foreground.
  watch               Run bench watch for asset rebuilds.
  autostart on|off    Whether the bench may come back after login.
  listen local|all    Where the web server and socketio listen: 127.0.0.1 (default) or every interface.
  path                Print the bench directory (used by benchcd).
  site list           The bench's sites; the default one is what benchup waits for.
  site add NAME       bench new-site (MariaDB password from the Keychain, a file on Linux), the hosts line, and
                      --bundle NAME or --apps "a b" from apps/. The default stays.
  site default NAME   Make NAME the default site (bench use, runner, benchup, the app).
  site hosts          Add a 127.0.0.1 line for every site to /etc/hosts (sudo, once).
  site backup NAME    bench --site NAME backup (--with-files for the uploads too; --json).
  site backups NAME   The site's backups, newest first: time, size, with files (--json).
  site snapshot NAME [--label TEXT]
                      Save the state of a site (database, files, site_config) in a folder frappe's
                      backup pruning never touches.
  site snapshots NAME The snapshots, newest first, and whether the bench's apps still match.
  site rollback NAME --to SNAPSHOT
                      Put a snapshot back (a reviewed plan; the current state is snapshotted first).
  site move NAME --to-bench PATH
                      Move a site to another registered bench (a reviewed plan: backup, restore
                      there, migrate, check, then the drop here; the backups stay).
  site restore NAME   Restore a backup set (--from STAMP or the database file's PATH, --from-site S)
                      into a site: it is backed up first, or --new creates it. --no-migrate,
                      --before-migrate SCRIPT, --with-files. --neutralise switches the restored
                      site's integrations off and clears its stored secrets (for a set that is
                      not this bench's own; an agent must pass it). --dry-run --json prints the plan with
                      its token; --apply TOKEN --yes [--json] runs exactly that plan.
  site drop NAME      bench drop-site: a backup with files first, the folder moved to
                      archived/sites, the hosts line removed. Needs --confirm-site NAME;
                      the default site also needs --new-default OTHER (--dry-run, --json).
  console             bench --site SITE console: a Python shell with frappe (--site S).
  db                  bench --site SITE mariadb: the site's database with its own user (--site S).
  open                Open the site in the browser (--site S, --path /app/...). --as USER signs in
                      as that user, no password; needs developer_mode and a person to run
                      "site open-as on" for the site. --print-url prints the link instead.
  users               Enabled users of a site for open --as (--site S, --search TEXT, --limit N).
  mariadb-password    Print the MariaDB root password (Keychain; a 0600 file on Linux; asks first).
                      A person's command: refused for agents, mcp and without a terminal.
  mcp                 Model Context Protocol server on stdio for coding agents
                      (claude mcp add benchbar -- benchbar mcp). Read tools, up, down, restart,
                      changes from a reviewed plan. --calls [N] prints the audit log.
  op status [OP_ID]   The long runs. Every command that changes things has an op_id (in its JSON
                      lines too); status shows one (or the ten newest) with its step and last
                      progress, list shows the recent ones, wait OP_ID [--timeout SECS] waits for
                      one to end. A run that died without a done line is interrupted.
  history             What ran on this machine, newest first: the command line (secrets as ***), who
                      started it (a terminal, the app, the tray, an agent through MCP, a script), the
                      bench, the times, the exit and what it changed. --bench PATH, --since 7d,
                      --limit N, --json.
  docs [TOPIC]        Open the documentation, or one topic's page (benchbar docs --help lists
                      them: install, doctor, apps, mcp, json ...); --print prints the URL.

Apps
  app list            Every app: branch, commit, local changes, the sites that have it
                      (--json; --no-sites reads the last site lists instead of asking bench).
  app add NAME|URL    bench get-app from config/apps.tsv or any git URL (GitHub, SSH, a
                      host alias), after checking access; --branch B, --name N, --commit SHA
                      (pin the clone to a commit), and --site S or --all-sites to install it.
                      Several apps in one plan: app add A --commit SHA B --install-on s1,s2
                      (--branch, --name, --commit and --install-on belong to the app before
                      them). Never replaces an app.
                      --dry-run --json: the plan with its token (required apps read from
                      hooks.py); --apply TOKEN --yes runs exactly that plan, no questions.
  app install NAME    Install an app of the bench on a site (--site S). --dry-run --json: the
                      plan with its token; --apply TOKEN --yes runs exactly that plan.
  app update NAME     Fast forward one app with a changelog first, back up the sites
                      that have it, then requirements, migrate and build (--skip-backup).
                      A run that stopped half way is finished by the next one (only the steps
                      left); --discard-pending drops that record and stops (nothing runs).
                      --dry-run --json: the plan with its token; --apply TOKEN --yes runs it.
  app focus [NAME]    Focus apps (the ones you work on: local changes, another branch, a
                      commit of yours in 14 days): doctor warns when an app they need falls
                      behind. No NAME lists them (--list, --json, --fetch); NAME pins it as
                      focus, --auto infers again.
  app unfocus NAME    Pin NAME as not a focus app.

Team lockfile (benchbar.toml: each app's repo, branch and commit, and the sites)
  lock write          Write it from this bench (asks, shows the diff, backs up the old one);
                      --lock PATH (remembered), --no-commits, --allow-dirty.
  lock check          Compare the bench with it: read only, no network, no database.
                      Exit 1 on any difference (--json).
  lock apply          Clone missing apps, switch branches, fast forward to pinned commits,
                      then requirements and build. Never touches a site or local work.
                      --dry-run --json: the plan with its token; --apply TOKEN --yes runs it.

Team profiles
  profile list        Built in and team profiles, with where each comes from (--json).
  profile show NAME   What a profile installs: base, Python, Node, MariaDB, apps.
  profile create NAME --from-bench PATH [--dir DIR]
                      Write a team profile from a bench (read only: app repos and
                      branches, the base from its frappe version). install --profile NAME
                      then builds the same bench on another Mac.
  profile export NAME [--out FILE] [--branch APP=BR]... [--drop APP]... [--plan]
                      A copy to share: SSH aliases resolved, each repo's default branch,
                      access (public, private, personal) and requires per app.
  profile import FILE|URL [--as NAME] [--plan]
                      Add a profile someone sent (https only, 64 KB at most); checks
                      which repos you can read. A GitHub page URL is fetched raw.
  profile subscribe GIT_URL [--plan]
                      Clone a team's config repo; its profiles join the lookup path.
  profile update NAME|--all [--plan]
                      Fetch an import or subscription again, show the diff, ask.
  profile remove NAME Move an import or a whole subscription aside.
  profile check NAME  Can git read every repo with your credentials? (--json)

Experiments (off until a person turns one on)
  labs [list]         The experiments and whether each is on (--json).
  labs on NAME        Turn one on, in a terminal, after its warning. Never from an agent.
  labs off NAME       Turn one off and undo what it started. labs status NAME: exit 1 when off.

Leases (a bench or a site held for a while, so nothing restarts, migrates, drops or restores it meanwhile)
  lease take          --bench PATH or --site NAME, --for MINUTES (default 30, at most 480), --note TEXT;
                      prints the lease id (--json). Set BENCHBAR_CALLER to a name for the holder;
                      an agent run without one cannot take a lease.
  lease renew ID      Push the end back (--for MINUTES).   lease release ID  Let go of it.
  lease list          The active leases (--bench PATH, --json). A lease id is shown to its holder
                      only. Pass --lease ID to a command that changes
                      what a lease covers; --break-lease is for a person at a terminal only.

Defaults that changed
  notices             The notices an update left (a new default and its way back), --json.
                      --dismiss ID or --all hides them (also in the BenchBar app).

Production copy
  pull HOST:SITE      Copy a production site over SSH into a NEW local site: the latest
                      backup on the server (nothing written there), the encryption key,
                      email muted, the scheduler paused and the copy neutralised
                      (integrations off, stored secrets cleared). HOST is from ~/.ssh/config.
    --as NAME         Local site name (default: SITE.local)
    --from-dir DIR    A backup set downloaded by hand (Frappe Cloud), no SSH
    --remote-bench D  The bench folder on the server (default ~/frappe-bench)
    --new-backup      Run bench backup on the server first (it also deletes older
                      backups there); asks for the site name, or --confirm-site SITE
    --replace         Restore over an existing local site, after backing it up
    --skip-app APP    Restore without APP (its tables stay behind as orphans)
    --no-files        Database only; --keep-scheduler, --keep-staging
    --keep-secrets    Leave the copy as production had it. By default it is neutralised:
                      outbound integrations off, stored secrets cleared, tokens and
                      queued mail dropped (the Administrator login is kept).
                      A person's decision: refused for agents and benchbar mcp
    --no-migrate      Stop after the restore, before bench migrate
    --before-migrate S  Run the executable SCRIPT after the restore, before migrate (with
                      BENCHBAR_SITE, BENCHBAR_BENCH, BENCHBAR_DB_NAME; no secret in its
                      environment); a failing script stops the run
                      The local site is created when it does not exist.

Options
  --bench-dir DIR     Bench to act on (default: remembered, or auto-detected)
  --site NAME         Site name (default: remembered, or from the bench)
  --profile NAME      Release profile for install/repair (default: v15-lts), or a team
                      profile (~/.config/benchbar/profiles/NAME.toml, BENCHBAR_PROFILE_PATH)
  --bundle NAME       App bundle for install (minimal, common, extended)
  --scratch, --ttl DAYS
                      install: the bench expires after DAYS (default 7); benchbar bench gc removes it
  --make-default      install, adopt, service: make this the default bench even when
                      another one is already the default
  --repair-bench      install: move a bench folder that is incomplete aside and start over (never
                      one that holds a site; --dry-run shows the move)
  --allow-windows-fs  install, adopt (WSL): accept a bench on the Windows file system
                      (/mnt/c, drvfs, 9p), which is slow and breaks file watching
  --allow-unsupported-distro
                      install (Linux): try a system other than Ubuntu 24.04, which is the one
                      the install is tested on and supports (at your own risk)
  --with-schedule     service: add the scheduler to Procfile.lean (per bench, kept by repair)
  --without-schedule  service: remove it again (the default)
  --port-offset N     install, adopt, service: use port block N (web 8000+N, socketio 9000+N,
                      redis 11000+N and 13000+N). Default: keep the ports, or the next
                      free block when another bench already uses them
  --dry-run           Print the full plan, change nothing
  --offline           install: skip the remote branch checks (also OFFLINE=1 or BENCHBAR_OFFLINE=1)
  -y, --yes           Do not ask; secrets must come from the environment
  --json              Versioned JSON for list, status and doctor; JSON lines for pull,
                      install, adopt, repair, up, down, restart, service, site add,
                      app update and ports apply (docs/json-schema.md)
  --lease ID          A lease you hold (benchbar lease take): the command may change what it covers
  --break-lease       A person at a terminal goes ahead although a lease covers the command
  --jsonl             JSON lines (plan, step, done) from any command that changes things
  --for-agent         --jsonl or --json, no questions (BENCHBAR_NONINTERACTIVE=1), no colors
  --background        install, repair, pull, app add, app update, site add, site backup, site restore,
                      site snapshot, site rollback:
                      start the run detached and print its op_id at once (needs --yes; no questions)
  benchbar COMMAND --help prints that command's flags and needs; benchbar commands --json lists them all
  --plain             No colors or spinners (also: NO_COLOR=1, or a non-TTY)
  -h, --help          This help
  --version           Print the version (and the BenchBar app's, when it is installed)

Environment:
  BENCHBAR_SUDO=gui   root steps (wkhtmltopdf, /etc/hosts) ask in a macOS password dialog, not sudo
  BENCHBAR_SUDO=env   Linux: sudo steps use the password in BENCHBAR_SUDO_PASSWORD, no terminal needed
  BENCHBAR_CALLER     Who started the run, for benchbar history: terminal, app, tray, mcp, agent or
                      script (set by the app, the tray and benchbar mcp; --for-agent says agent)
  BENCH_INIT_TIMEOUT_SECONDS   install: how long bench init may run (default 2700, 0 for no limit)
  BENCHBAR_LENIENT_FLAGS=1     an unknown option is a warning, not an error (exit 64), as before 0.9.0

Shell helpers (written to your shell rc by install or repair):
  benchup benchdown benchrestart benchstatus benchlogs benchfg benchwatch benchdoctor benchcd

Documentation: @DOCS@/
