Scope, all under windows/shim (Go 1.23 or newer, standard library only unless a dependency saves real code; justify it in DECISIONS):
1. Forwarding: `benchbar.exe ARGS` runs `wsl.exe -d <distro> --cd ~ -- benchbar ARGS`, with stdin, stdout and stderr passed through untouched (no line translation, so JSON and MCP's stdio framing survive). It exits with the CLI's exit code; 0, 1 and 2 keep their meanings. A missing distro or a missing `benchbar` inside it exits 1 with one line naming the fix. Signals: Ctrl+C in PowerShell reaches the Linux process (test with a fake wsl.exe that records what it received). Arguments containing spaces, quotes, `$`, backslashes and non ASCII survive the hop: wsl.exe re-parses its command line, so pick and test the quoting.
2. Which distro: a `distro` key in `%LOCALAPPDATA%\BenchBar\config.json`, else the WSL default distro. `benchbar.exe adopt-distro [NAME]` checks that the distro is WSL 2, has systemd enabled (`/etc/wsl.conf` `[boot] systemd=true`), has `benchbar` on PATH, and has `loginctl` linger for the user. It reports each check like doctor (`[OK]`, `[WARN]`, `[FAIL]` with a `fix:` line), records the distro, and changes nothing inside the distro without a yes.
3. `.wslconfig`: `benchbar.exe wslconfig` reads `%USERPROFILE%\.wslconfig` and reports memory, processors, swap and `vmIdleTimeout`. `--suggest` prints the lines a bench needs: memory at least 4 GB, and `vmIdleTimeout=-1` so WSL does not stop a running bench when the last terminal closes. It writes the file only with `--apply --yes`, after a backup beside it, keeping other keys and comments. Never write anything into the distro from Windows.
4. Logon keep alive: `benchbar.exe keepalive install` registers a Task Scheduler task at logon, interactive only, hidden (the same pattern as windows/runner/setup-runner.ps1). It runs `wsl.exe -d <distro> --exec /bin/true` and then keeps one idle `wsl.exe -d <distro> --exec sleep infinity` alive, so the distro, and with linger the benches that were running, come back after a reboot without a terminal. Add `keepalive remove` and `keepalive status`. No Windows service, no admin rights.
5. Pass through that must work from PowerShell, exactly as on the Mac: `benchbar.exe status --json`, `doctor --json`, `list --json`, `up`, `down`, and `benchbar.exe mcp` (stdio, so `claude mcp add benchbar -- benchbar.exe mcp` works in a Windows Claude Code).
