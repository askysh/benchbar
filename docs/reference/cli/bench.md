The end of a bench's life. The guide is
[Benches and sites](../../guides/benches-and-sites.md#retiring-a-bench). Every
command takes the [options for every command](install.md#options-for-every-command).

`forget`, `remove` and `gc` are plans with a token, as
[site restore](site.md#site-restore): `--dry-run --json` prints the plan and
its token, `--apply TOKEN --yes` runs exactly that plan, and a token
whose plan changed since is refused. Nothing here deletes a folder.

## bench forget

```
benchbar bench forget PATH [--dry-run [--json] | --apply TOKEN --yes [--json]]
```

Unregisters a bench. The bench is stopped, its launchd agent (systemd unit on
Linux), runner, `Procfile.lean` and listen files are backed up and moved
aside, it leaves the list `benchbar register` keeps, and its settings file
moves to `<state folder>/forgotten/`. When it was the default bench there is
no default afterwards: another bench never takes over on its own. The folder
with its sites, apps and databases stays, and so do the hosts lines
(`benchbar site hosts --prune` removes the lines of sites no bench has). The
shell helper block stays while another bench has a service.

A bench that is only found by looking in the usual folders (`~/frappe-bench`,
and so on) has nothing to forget: it shows in `benchbar list` as long as its
folder exists.

An agent may run it, with the plan and its token: it is undone with
`benchbar adopt PATH`.

## bench remove

```
benchbar bench remove PATH --dry-run --json
benchbar bench remove PATH --confirm-bench NAME --apply TOKEN --yes
```

`forget`, plus: each site is backed up with its files and its database is
dropped (`bench drop-site`, which moves the site folder to `archived/sites`),
then the bench folder is renamed into `<parent>/.benchbar-trash/NAME-DATE`.
Benchbar never deletes that folder; it holds the backups, so empty it yourself
when you are sure. `--confirm-bench` repeats the folder's name, as
`site drop --confirm-site` does. The default bench is refused. Needs the
MariaDB root password like `site drop`.

A person's decision: refused under `BENCHBAR_NONINTERACTIVE`, `--for-agent` and
`mcp`, and without a terminal. The plan (`--dry-run`) is open to agents.

## bench scratch

```
benchbar bench scratch PATH [--ttl DAYS] [--clear] [--json]
benchbar install --scratch [--ttl DAYS]
```

Marks a bench scratch: it expires after `--ttl` days (1 to 90, default 7).
`install --scratch` marks the new bench once it is set up; it cannot be
combined with `--make-default`. `--clear` keeps the bench. The mark is in the
bench's settings file, so `forget` and `remove` take it away too.

## bench gc

```
benchbar bench gc --dry-run [--json]
benchbar bench gc --apply TOKEN --yes
```

Lists the scratch benches that expired (`expired`), the ones that have not
yet (`pending`) and the ones it keeps (`skipped`: the default bench is never
collected). Applying removes each expired bench as `bench remove` does, in
order, and stops at the first failure. Applying is a person's decision, like
`bench remove`; the plan is open to agents.

```bash
benchbar install --scratch --ttl 3 --bench-dir ~/dev/try-v16 --profile v16-lts
benchbar bench gc --dry-run
benchbar bench gc --dry-run --json
benchbar bench gc --apply TOKEN --yes
```
